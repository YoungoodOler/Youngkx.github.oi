> From Bits to Instructions: Understanding the Foundations of Computer Science

## 前言

我们每天都在使用计算机。

无论是运行一个 C++ 程序、打开网页，还是训练一个神经网络，计算机都能够按照我们的要求完成复杂的任务。

但如果继续追问：

- 计算机为什么能够理解程序？
- CPU 究竟在执行什么？
- 一条简单的加法指令如何转化为硬件操作？
- 内存、寄存器与 CPU 之间是什么关系？
- 为什么仅仅使用 0 和 1，就能够构建现代计算机？

这些问题都指向计算机科学中一个非常重要的领域：**计算机组成原理（Computer Organization）**。

为了更直观地理解这些概念，我们可以从一台简化的计算机开始。

通过一个交互式 HTML 计算机模型，我们可以观察数据的存储、指令的执行，以及计算机内部状态的变化。

文中的汇编示例用于说明通用概念，第六节的三维实验台使用自己的指令编码。

## 一、计算机为什么使用二进制？

### 1.1 从十进制到二进制

在日常生活中，我们习惯使用十进制（Decimal）。

例如：

**125 = 1 × 10² + 2 × 10¹ + 5 × 10⁰**

计算机内部则广泛使用二进制（Binary）。

二进制只有两个数字：

**0，1**

例如，二进制数 `1101` 对应的十进制数为：

**(1101)₂ = 1 × 2³ + 1 × 2² + 0 × 2¹ + 1 × 2⁰ = 13**

二进制的每一位称为一个 **Bit（比特）**。

8 个 Bit 组成一个 Byte（字节）。

因此，一个字节能够表示：

**2⁸ = 256**

种不同的状态。

如果将它解释为无符号整数，其取值范围就是：

**0～255**

### 1.2 为什么计算机选择二进制？

这与电子电路的物理特性密切相关。

对于数字电路而言，区分两个稳定的逻辑状态相对容易。

我们可以抽象地将其表示为：

| 逻辑值 | 电路状态 |
|---|---|
| 0 | 低电平 |
| 1 | 高电平 |

需要注意，0 和 1 并不意味着电压一定是 0V 和 1V。它们只是对电路状态的逻辑抽象。

通过大量晶体管的组合，我们能够构建逻辑门、加法器、寄存器，最终构成 CPU。

**计算机使用二进制，并不是因为二进制更适合人类理解，而是因为它非常适合使用电子电路实现可靠的信息处理。**

## 二、从逻辑门到运算器

计算机能够执行复杂运算，但最底层的数字逻辑操作并不复杂。

### 2.1 基本逻辑运算

常见的逻辑运算包括：

**与运算（AND）**

只有两个输入都为 1，输出才为 1。

**1 ∧ 1 = 1**

**或运算（OR）**

只要至少一个输入为 1，输出就是 1。

**1 ∨ 0 = 1**

**非运算（NOT）**

将逻辑状态取反。

**¬1 = 0**

**异或运算（XOR）**

当两个输入不同时，输出为 1。

**1 ⊕ 0 = 1**

### 2.2 计算机如何实现加法？

考虑最简单的情况：两个一位二进制数相加。

**1 + 1 = (10)₂**

结果需要两个二进制位表示。

其中：

- 低位为 0，称为和（Sum）。
- 高位为 1，称为进位（Carry）。

我们可以利用 XOR 和 AND 构建半加器（Half Adder）。

**Sum = A ⊕ B**

**Carry = A ∧ B**

在此基础上，再考虑来自低位的进位，就能够构建全加器（Full Adder）。

通过组合多个全加器，可以实现多位二进制加法。

现代 CPU 中的算术逻辑单元（Arithmetic Logic Unit，ALU），正是建立在这些数字逻辑基础之上。

当然，实际 ALU 的设计远比简单加法器复杂，还需要支持减法、比较、移位和逻辑运算等功能。

## 三、计算机的基本组成

### 3.1 冯·诺依曼体系结构

现代通用计算机的重要理论基础之一，是冯·诺依曼体系结构（Von Neumann Architecture）。

其核心思想是：

**程序指令与数据都可以采用二进制形式存储在存储器中。**

计算机不需要为每一个任务重新连接电路，而是可以通过读取不同的程序指令执行不同任务。

一个简化的计算机系统可以表示为：

```text
            +-------------------+
            |       CPU         |
            |                   |
            |  +-------------+  |
            |  | Control Unit|  |
            |  +-------------+  |
            |                   |
            |  +-------------+  |
            |  |     ALU     |  |
            |  +-------------+  |
            |                   |
            |    Registers      |
            +---------+---------+
                      |
                Address / Data
                      |
            +---------+---------+
            |       Memory      |
            |                   |
            | Instructions      |
            | Data              |
            +-------------------+
```

这个模型中，最值得关注的是 CPU、寄存器和存储器之间的协作。

### 3.2 CPU：计算机的指令执行核心

CPU（Central Processing Unit，中央处理器）负责执行程序指令。

从功能上看，可以将其理解为几个主要部分。

**控制单元（Control Unit）**

负责解释指令并协调其他部件完成操作。

例如，当 CPU 读取到一条加法指令时，控制单元需要组织相应的数据读取和运算过程。

**算术逻辑单元（ALU）**

负责执行算术和逻辑运算。

例如：

```text
ADD
SUB
AND
OR
XOR
```

**寄存器（Registers）**

用于保存 CPU 当前正在处理的数据、地址和控制状态。

寄存器通常位于处理器内部，具有很低的访问延迟。

### 3.3 寄存器与内存有什么区别？

可以将寄存器理解为 CPU 工作时直接使用的少量高速存储位置。

而内存（Memory）负责存储更大规模的程序和数据。

| 对比项目 | 寄存器 | 主存（RAM） |
|---|---|---|
| 位置 | 通常位于 CPU 内部 | 通常位于 CPU 外部 |
| 容量 | 很小 | 较大 |
| 访问延迟 | 通常很低 | 通常较高 |
| 主要用途 | 保存当前运算数据与处理器状态 | 存储程序和运行数据 |

例如，计算：

**C = A + B**

在一个简单的寄存器机器中，可以先将 A 和 B 从内存加载到寄存器，再由 ALU 完成加法，最后把结果写回内存。

这说明一个重要事实：

**CPU 的运算、数据的存储以及数据的传输，是三个相互关联但并不相同的过程。**

## 四、计算机如何理解指令？

### 4.1 从高级语言到机器指令

假设我们编写下面的 C++ 代码：

```cpp
int a = 5;
int b = 3;
int c = a + b;
```

对于程序员而言，这段代码的含义非常明确。

但 CPU 并不能直接理解 C++ 语法。

在通常的编译执行流程中，编译器会将源代码转换为目标机器架构能够执行的机器指令。

为了便于阅读，我们通常使用汇编语言（Assembly Language）表示这些指令。

例如，在某种假设的简化指令系统中：

```asm
LOAD R1, 5
LOAD R2, 3
ADD  R1, R2
STORE R1, 100
```

这些指令的含义分别是：

| 指令 | 含义 |
|---|---|
| LOAD R1, 5 | 将数值 5 放入寄存器 R1 |
| LOAD R2, 3 | 将数值 3 放入寄存器 R2 |
| ADD R1, R2 | 将 R1 与 R2 相加，结果保存到 R1 |
| STORE R1, 100 | 将 R1 的值写入内存地址 100 |

这里的 `LOAD` 被定义为加载立即数，是为了教学方便。真实处理器中，加载立即数与从内存加载数据往往使用不同指令或不同寻址方式。

上述代码仅用于说明指令的工作原理，并不是某种真实 CPU 的标准汇编语法。

### 4.2 指令集架构（ISA）

不同 CPU 能够理解的指令并不一定相同。

定义处理器软件可见行为的规范，称为指令集架构（Instruction Set Architecture，ISA）。

它通常规定：

- 支持哪些机器指令；
- 指令如何编码；
- 有哪些程序员可见的寄存器；
- 数据如何寻址；
- 运算结果如何表示；
- 程序如何进行跳转与控制。

常见的 ISA 包括：

- x86-64
- ARM
- RISC-V

需要区分两个概念：

**ISA 描述处理器对软件提供什么功能，而微架构（Microarchitecture）描述处理器内部如何实现这些功能。**

因此，两款内部设计完全不同的 CPU，也可能执行同一种 ISA 的程序。

## 五、一条指令究竟如何执行？

这是理解简单计算机模型最关键的部分。

### 5.1 取指—译码—执行循环

在一个经典的简化处理器中，CPU 可以按照以下过程运行：

```text
        +------------------+
        | Fetch            |
        | 取指             |
        +--------+---------+
                 |
                 v
        +------------------+
        | Decode           |
        | 译码             |
        +--------+---------+
                 |
                 v
        +------------------+
        | Execute          |
        | 执行             |
        +--------+---------+
                 |
                 v
        +------------------+
        | Update State     |
        | 更新状态         |
        +--------+---------+
                 |
                 +----> 下一条指令
```

这个过程通常称为指令周期（Instruction Cycle）。

实际处理器可能使用流水线、乱序执行等复杂机制，但这个模型仍然有助于理解程序执行的基本语义。

### 5.2 程序计数器 PC

程序计数器（Program Counter，PC）用于记录程序执行位置。

在一个简单模型中，它保存下一条待取指令的地址。

例如：

```text
PC = 0
```

CPU 从地址 0 读取指令。

执行完成后，如果指令没有改变控制流，PC 就更新为下一条指令的地址。

需要注意，PC 不一定每次都加 1。

在真实计算机中，指令可能占据多个字节，因此 PC 的变化与指令长度及处理器架构有关。

### 5.3 指令寄存器 IR

指令寄存器（Instruction Register，IR）可以用于保存当前取出的指令。

例如：

```text
IR = ADD R1, R2
```

控制单元根据指令的编码，判断应该执行哪一种操作。

这里的 IR 是教学模型中的一个显式寄存器。实际 CPU 的指令保存与译码机制可能更加复杂。

下面用同一个加法任务，拆解简化指令与寄存器状态的对应关系。

现在，我们设计一台非常简单的教学计算机。

假设它具有：

- 两个通用寄存器：R1、R2；
- 一个程序计数器：PC；
- 一个指令寄存器：IR；
- 一个 ALU；
- 一段能够存储程序与数据的内存。

为了简化演示，规定每条指令占用一个地址单元，PC 在顺序执行时增加 1。

### 6.1 初始程序

我们的目标是计算：

**5 + 3 = 8**

程序如下：

```asm
0: LOAD R1, 5
1: LOAD R2, 3
2: ADD  R1, R2
3: STORE R1, 100
4: HALT
```

其中 `HALT` 表示停止程序执行。

初始状态：

```text
PC = 0

R1 = 0
R2 = 0

Memory[100] = 0
```

### 6.2 第一步：加载第一个操作数

CPU 根据 PC 的值读取地址 0 中的指令：

```asm
LOAD R1, 5
```

执行后：

```text
R1 = 5
R2 = 0

PC = 1
```

### 6.3 第二步：加载第二个操作数

CPU 读取地址 1：

```asm
LOAD R2, 3
```

执行后：

```text
R1 = 5
R2 = 3

PC = 2
```

### 6.4 第三步：执行加法

CPU 读取：

```asm
ADD R1, R2
```

控制单元指示 ALU 对两个寄存器中的数据进行加法运算。

**R1 ← R1 + R2**

执行后：

```text
R1 = 8
R2 = 3

PC = 3
```

### 6.5 第四步：写回内存

CPU 执行：

```asm
STORE R1, 100
```

将 R1 中的数值写入内存地址 100。

```text
Memory[100] = 8

PC = 4
```

最后执行：

```asm
HALT
```

程序停止。

### 6.6 观察整个执行过程

| 执行步骤 | 指令 | R1 | R2 | Memory[100] |
|---|---|---:|---:|---:|
| 初始状态 | — | 0 | 0 | 0 |
| 1 | LOAD R1, 5 | 5 | 0 | 0 |
| 2 | LOAD R2, 3 | 5 | 3 | 0 |
| 3 | ADD R1, R2 | 8 | 3 | 0 |
| 4 | STORE R1, 100 | 8 | 3 | 8 |
| 5 | HALT | 8 | 3 | 8 |

整个过程中，我们没有改变计算机的硬件结构。

改变的只是寄存器、内存和程序执行状态。

这正是通用可编程计算机的重要特征。

## 七、程序如何改变执行顺序？

到目前为止，我们看到的程序都是从上到下顺序执行。

但真正的程序还需要条件判断、循环和函数调用。

这些功能都离不开控制流（Control Flow）。

### 7.1 跳转指令

假设存在一条指令：

```asm
JMP 10
```

它的作用是将 PC 设置为 10。

于是 CPU 下一次就会从地址 10 取指令，而不是继续读取原本的下一条指令。

### 7.2 条件跳转

进一步假设，我们定义：

```asm
JZ R1, 10
```

含义为：

如果 R1 的值为 0，则跳转到地址 10。

否则继续顺序执行。

这样就能够实现条件判断。

例如，高级语言中的：

```cpp
if (x == 0) {
    // ...
}
```

在机器指令层面，通常可以通过比较或测试操作配合条件跳转实现。

### 7.3 循环的本质

考虑：

```cpp
while (x > 0) {
    x--;
}
```

在底层，循环并不是一种神秘的结构。

它可以被分解为：

1. 检查条件；
2. 根据条件决定是否跳转；
3. 执行循环体；
4. 跳回条件检查位置。

因此，从机器指令的角度看：

**顺序执行、条件跳转与无条件跳转，已经能够表达大量常见的程序控制结构。**

## 八、时钟周期与计算机性能

### 8.1 CPU 为什么需要时钟？

许多同步数字电路依靠时钟信号协调状态更新。

时钟频率通常使用 Hz 表示。

例如：

**3 GHz = 3 × 10⁹ 周期/秒**

表示每秒约有 30 亿个时钟周期。

但这并不意味着 CPU 每秒恰好执行 30 亿条指令。

### 8.2 时钟周期不等于指令数量

一条指令可能需要多个周期才能完成。

另一方面，现代处理器也可能通过流水线和多发射机制，在一个周期内完成多条指令。

因此，性能不能仅由频率决定。

一个常见的简化性能模型为：

**CPU Time = (Instruction Count × CPI) / Clock Rate**

其中：

- Instruction Count：执行的指令数量；
- CPI：平均每条指令所需的时钟周期数；
- Clock Rate：时钟频率。

例如，假设某程序执行了 10 亿条指令，平均 CPI 为 2，CPU 频率为 2 GHz。

那么：

**CPU Time = (10⁹ × 2) / (2 × 10⁹) = 1 s**

在这些假设成立的情况下，程序的 CPU 执行时间为 1 秒。

现实中，缓存命中率、内存访问、分支预测、处理器微架构等因素也会影响性能。

## 九、从简单计算机到现代计算机

前面的模型已经能够帮助我们理解程序执行的基本过程。

但真实计算机还需要解决更多问题。

### 9.1 存储层次结构

寄存器的速度很快，但容量有限。

主存容量较大，但访问延迟通常更高。

因此，现代计算机引入了多级存储结构：

```text
       Registers
           |
        L1 Cache
           |
        L2 Cache
           |
        L3 Cache
           |
       Main Memory
           |
      SSD / Storage
```

越靠近 CPU 的存储层级，通常访问延迟越低，但容量也更小、单位容量成本更高。

缓存（Cache）的核心目标，就是利用程序访问数据时的局部性，提高平均访问效率。

### 9.2 流水线

在简单模型中，我们可以认为 CPU 完成一条指令后，再开始执行下一条。

但现代处理器通常会让多条指令的不同执行阶段重叠。

例如：

```text
Cycle     1   2   3   4   5
Instr 1   F   D   E   M   W
Instr 2       F   D   E   M
Instr 3           F   D   E
```

这里：

- F：Fetch
- D：Decode
- E：Execute
- M：Memory Access
- W：Write Back

这是一种典型的五级流水线教学模型，并不代表所有 CPU 都采用相同设计。

流水线可以提高指令吞吐量，但也会引入数据相关、控制相关等问题。

### 9.3 多核处理器

单个 CPU 核心可以执行一条指令流。

现代处理器通常包含多个核心，使多个执行任务能够在不同核心上并行运行。

但多核并不意味着所有程序都能自动获得成倍的性能提升。

程序是否能够有效并行、任务之间是否存在依赖，以及共享资源的竞争程度，都会影响最终性能。

## 十、计算机科学中的抽象层次

理解计算机还有一个非常重要的角度：抽象（Abstraction）。

从物理电路到高级程序，计算机系统可以被划分为多个层次。

```text
+---------------------------+
| Applications              |
| 应用程序                  |
+---------------------------+
| High-level Languages      |
| C / C++ / Python          |
+---------------------------+
| Compiler / Runtime        |
| 编译器与运行时            |
+---------------------------+
| Instruction Set           |
| 指令集架构                |
+---------------------------+
| Microarchitecture         |
| 处理器微架构              |
+---------------------------+
| Digital Logic             |
| 数字逻辑电路              |
+---------------------------+
| Transistors               |
| 晶体管与物理器件          |
+---------------------------+
```

这个分层图是概念上的简化，并非严格的一对一实现关系。例如，解释器、操作系统和固件也会参与实际程序的运行。

对于程序员而言，抽象最大的意义在于：

**我们不需要每次编写程序时，都重新思考晶体管应该如何导通。**

编程语言帮助我们表达算法，编译器将程序转换为目标平台可以执行的形式，处理器再依据其架构和实现完成运算。

但抽象并不意味着底层知识不重要。

当我们研究性能优化、内存布局、并发程序、编译器或操作系统时，底层的计算机组成知识往往会重新变得关键。

## 十一、为什么要制作一台简单计算机？

学习计算机科学时，我们很容易陷入一种状态：

知道许多术语，却无法把它们连接成完整的系统。

例如，我们可能分别知道：

- CPU 用于执行指令；
- 内存用于存储数据；
- 寄存器的访问速度很快；
- 程序由一系列指令组成。

但如果没有观察过程序执行时的状态变化，这些概念就容易停留在文字层面。

一台交互式简单计算机的价值，正是在于让抽象过程变得可观察。

我们可以尝试回答以下问题：

1. 当 PC 改变时，下一条执行的指令是否发生变化？
2. 当 ALU 完成运算时，结果首先保存在哪里？
3. 为什么修改某个寄存器的值，会影响后续指令？
4. 一条跳转指令为什么能够形成循环？
5. 如果程序访问了错误的内存地址，会发生什么？

这些问题看似基础，却是进一步学习计算机体系结构、操作系统和编译原理的重要起点。

当然，教学模拟器也有局限。

它通常会忽略真实硬件中的电路传播延迟、缓存一致性、异常处理、流水线冲突以及复杂的内存管理机制。

因此，我们应当将它理解为一种**帮助建立计算机运行模型的工具**，而不是完整的真实处理器仿真。

---

## 十二、结语

回到最初的问题：

计算机究竟是如何执行程序的？

从最基本的层面看，计算机通过数字电路表示和处理信息，通过存储器保存数据与指令，通过控制单元组织执行过程，通过 ALU 完成运算，并不断更新内部状态。

一条条简单指令组合起来，就能够实现条件判断、循环、函数调用以及复杂的算法。

从二进制到逻辑门，从寄存器到 CPU，从机器指令到高级语言，我们看到的并不是彼此孤立的知识点，而是一个逐层构建起来的完整系统。

**计算机的强大，并不来自某一条特别复杂的指令，而是来自简单操作能够被精确、快速且大规模地组合。**

理解这一点，也就真正开始理解计算机科学。
