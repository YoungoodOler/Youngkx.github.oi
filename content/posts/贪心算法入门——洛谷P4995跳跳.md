# 贪心算法入门

## 1. 贪心是什么？

**每一步按某个规则，选择当前最有利的方案，不再回头修改之前的选择。** 这就是贪心算法的基本想法。

### 从一个简单的例子理解

假设要买 5 支相同的笔，甲店每支 2 元，只剩 3 支；乙店每支 4 元，数量足够，而且没有运费等额外费用。

我们会先把甲店的 3 支买下，再到乙店买剩下的 2 支，总共花 `3 × 2 + 2 × 4 = 14` 元。

这里的选择规则就是：**还有便宜的，就优先买便宜的。** 每一步都尽量少花钱，希望最后的总费用也最少。

为什么这个规则可靠？如果买了乙店的贵笔，甲店却还有便宜笔没买，那么换成甲店的笔，数量不变，费用还能减少。因此，便宜的先买不会吃亏。

### “当前最好”和“最后最好”有什么区别？

- **局部最优：** 只看当前这一步，选择最有利的做法。
- **全局最优：** 看所有步骤完成后的结果，得到题目要求的最好答案。

贪心算法想做的，就是通过一连串局部选择，得到全局最优。

它与“把所有方案都试一遍”不同：贪心确定规则后，每一步直接作出选择，通常不用枚举后面所有可能的情况，也不回头撤销之前的决定。因此，合适的贪心算法往往比较简洁、运行也快。

但要注意：**当前最好，不一定能让最后最好。**

例如，用面值为 `1、3、4` 的硬币凑出 6，希望硬币数量最少。如果每次都选不超过剩余金额的最大面值，会得到 `4 + 1 + 1`，需要 3 枚；而 `3 + 3` 只需要 2 枚。这说明“每次选最大的”并不是任何时候都正确。

所以，做贪心题的重点不是背“选最大”或“选最小”，而是想清楚：**这道题每一步应该按什么规则选择？这样选会不会影响后面的结果？**

下面结合 [洛谷 P4995《跳跳！》](https://www.luogu.com.cn/problem/P4995) 来看。

## 2. 这道题要做什么？

有 `n` 块高度不同的石头，从高度为 `0` 的地面出发，每块石头恰好跳一次，最后停在任意石头上，不能再跳回地面。

从高度 `x` 跳到高度 `y`，耗费的体力是：

```text
(x - y) × (x - y)
```

要求的是**最大体力消耗**。注意，是越累越好！

输入：第一行是石头数量 `n`，第二行是 `n` 个高度。输出：最大体力消耗。

## 3. 怎么贪心？

### 第一步：先明确要优化什么

题目求的不是跳得最高，也不是总高度最大，而是每次跳跃的体力消耗加起来最大。

每次的消耗由**两块石头的高度差**决定。例如，高度差为 1，消耗是 1；高度差为 5，消耗就是 25。无论向上跳还是向下跳，只要高度差相同，消耗就相同。

因此，我们希望不断在高石头与低石头之间跳，让高度差尽可能大。

### 第二步：确定每一步的选择规则

最初在高度为 0 的地面，所有石头都比地面高，所以先考虑跳到最高的石头。

到了最高处，剩下的石头都在下面，跳到最低的石头，高度差最大。接着，到了最低处，剩下的石头都在上面，就跳到剩下最高的石头。

继续这样选择，就得到本题的贪心顺序：

> 从地面跳到最高的，再跳到最低的，再跳到剩下最高的，再跳到剩下最低的……

这里“当前最有利”的含义，是让这一次跳跃的高度差最大。选过的石头不能再选，于是每一步都在**剩下的石头**中考虑。

### 第三步：理解为什么要高低交替

如果连续跳高度接近的石头，虽然也访问了石头，却只能得到较小的体力消耗。把较高与较低的石头交错安排，能产生更多大跨度的跳跃。

而且，每次取走最高或最低的一块后，剩下的高度仍然处于一个连续的排序区间里：站在刚取出的高处，剩下的都更低；站在刚取出的低处，剩下的都更高。因此，这条规则可以一直执行下去。

这解释了策略的直观动机和执行过程；严格说明总和最优，还需要比较不同顺序，不能只凭“这一步最大”就当作证明。本题可以使用上述两端交替的贪心策略，但“每次挑最远的”不能直接套到所有路径问题中。

### 第四步：手动模拟，再写代码

例如，高度为 `1、2、3、4`（自拟示例）：

```text
跳跃顺序：0 → 4 → 1 → 3 → 2
体力消耗：16 + 9 + 4 + 1 = 30
```

| 次数 | 当前高度 | 剩下的高度 | 本次选择 | 消耗 |
| --- | ---: | --- | ---: | ---: |
| 1 | 0 | 1、2、3、4 | 最高的 4 | 16 |
| 2 | 4 | 1、2、3 | 最低的 1 | 9 |
| 3 | 1 | 2、3 | 最高的 3 | 4 |
| 4 | 3 | 2 | 剩下的 2 | 1 |

如果按从小到大跳：`0 → 1 → 2 → 3 → 4`，消耗只有 `1 + 1 + 1 + 1 = 4`。

实现时，先把高度从小到大排序。用 `l` 指向剩下最矮的石头，`r` 指向剩下最高的石头，从右端、左端、右端、左端交替取数即可。

回头看这道题的思考过程：**先看目标是最大消耗，再看消耗取决于高度差，最后得到高低交替的选择规则。** 贪心规则应该从题目目标推出来，而不是一开始就猜“排序后怎么取”。

## 4. 完整代码

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

int h[305] = {};  // 初始化为0
long long ans = 0;

int main(){
    int n;
    cin >> n;
    for (int i = 1; i <= n; i++) cin >> h[i];

    sort(h + 1, h + n + 1);  // 高度从小到大排序

    int l = 1, r = n;
    int now = 0;     // 当前高度，最初在地面
    
    for (int i = 1; i <= n; i++){
        int next;
        if (i % 2 == 0) next = h[r--];  // 第 1、3、5……次取最高的
        else next = h[l++];  // 第 2、4、6……次取最低的

        ans += (now - next) * (now - next);
        now = next;
    }

    cout << ans;
    return 0;
}
```

## 5. 对着代码看思路

- `sort(h + 1, h + n + 1)`：把 `h[1]` 到 `h[n]` 排成升序。
- `l` 和 `r`：分别指向剩下最矮、最高的石头。取完后移动对应下标。
- `i % 2 == 0`：循环从 `i = 1` 开始，所以第一次取最高，第二次取最低，交替进行。
- 算完后更新当前高度 `now`。

只循环 `n` 次，每块石头取一次，不需要真的删除数组元素，也不需要保存整个跳跃顺序。

**注意两点：** 答案用 `long long`，多次平方累加可能超过 `int`；结束后不要再加一次跳回地面的消耗，题目不允许跳回去。

时间复杂度为 `O(n log n)`，主要花在排序；数组存储空间为 `O(n)`。
