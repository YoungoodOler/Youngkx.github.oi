## 可复现方法

在项目根目录，先安装锁定依赖并确保 `node --version` 是 `v22.23.4`：

```powershell
npm ci
node scripts/benchmarks/run.mjs <label> all
node scripts/benchmarks/browser.mjs <label>
npm run test:e2e
```

`label` 仅允许小写字母、数字及连字符。使用新名称保留原始结果，不要覆盖本次 `before`、`after` 等目录。

如需复现旧版本，先把 `scripts/benchmarks/` 复制到外部目录，再在独立 checkout 中检出上述基准提交、复制脚本、运行 `npm ci`。不要在有未提交工作的目录里切换版本。性能阶段必须使用原始锁文件；安全更新后的版本不用于归因代码优化收益。

- `run.mjs` 顺序执行类型、lint、单元/Workers 运行时测试，再做三轮生产构建和性能预算。每次只清理经过路径检查的 `.next/` 与 `out/`，不删除依赖或 `.wrangler/` 数据。
- 每个命令记录墙钟时间、退出码、日志与 Node `resourceUsage()` 原始数据。预加载脚本覆盖可继承 `NODE_OPTIONS` 的 Node 子进程。
- 内存指标是**单个 Node 进程的 RSS 高水位最大值**，不是同时运行的整个进程树内存、堆大小或线上 Worker 内存。多次构建取各轮峰值的中位数。
- 所有结果保留全部样本，汇总默认使用中位数。降低指标的改善幅度为 `(优化前 - 优化后) / 优化前 × 100%`。负值代表回退。
- 每次清理构建输出不等于重置操作系统文件缓存、字体下载缓存或后台进程。首次构建、机器负载、计时器和 GC 均有噪声；小幅差异不解释为确定收益。
- `runtime.mjs` 用真实业务 Worker 代码和固定存储 fixture，每个 binding 操作注入相同的 20 ms 延迟；两次预热后记录十次请求的时间及操作清单。它验证请求关键路径和调用数量，**不是线上 Cloudflare 延迟**。
- `browser.mjs` 使用本机 Edge headless、固定时区/语言、桌面 1440×900 与移动端 390×844、DPR=1、减少动态效果、暗色主题；本地无压缩静态 HTTP、`no-store`，各五个全新浏览器 context。页面 `/articles/` 等待 canvas 可见后再等待 2 秒，记录 Navigation/Paint/LCP 和 CDP JS 堆。截图遮住随时间变化的背景 canvas，保留其他页面布局。原始 `scriptDurationSeconds` 因计数器在等待后启用而不用于比较。
- INP、线上 TTFB/吞吐量、生产 Worker CPU/RSS、GPU/整机内存、真实网络节省均**未测量**。本地数据不得替代线上结论。

## 优化与验证结果

### 已实施的低风险优化

| 改动                  | 原因与结果                                                                                                                             |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 性能预算缓存资源大小  | 每次 CLI 调用内，同一 JS/CSS 只读取和 Brotli 压缩一次。保持压缩参数、预算、逐页检查与错误行为，缓存不跨构建                            |
| 文件列表并行读取      | 设置和访问权限检查后，并行读取目录与文件元数据。保留分页、排序、公开开关及失效目录处理，不引入跨请求缓存                               |
| Range HEAD 复用元数据 | 复用 Range 校验时已有的 R2 对象信息，整个请求的 binding 操作由 4 次降至 3 次；保留 206、416、If-Range 和空响应体                       |
| JSON 流清理与错误处理 | 在所有出口释放 reader；取消超限请求失败时仍保留 BODY_TOO_LARGE。新增测试在原实现上复现了 3 个失败断言，见 `before/http-regression.log` |
| 可选浏览器存储        | 集中存储异常处理及管理 token 键。浏览器禁用存储或达到配额时，主题和管理功能仍使用内存状态；不再把存储失败当成鉴权失败                  |
| 标题锚点唯一性        | 修复 `Example`、重复 `Example` 与 `Example-2` 生成相同 id 的碰撞；现有五篇 Markdown 的完整解析结果和 HTML 保持一致                     |
| 共用文章类型          | `ArticleRecord` 复用 Markdown 类型，消除重复字段定义；保留已有导出名称                                                                 |
